# Архитектура

Приложение состоит из домашнего виджета `RemoteViews` и экрана настройки. `AgendaViewsService` строит прокручиваемую коллекцию из локального индекса; `WidgetAgenda` проецирует активные задачи в группы «Просрочено», «Сегодня», «Завтра», даты и «Без даты». Виджет не перечитывает Markdown при каждой перерисовке. Название задачи окрашивается по датам: до Start — белый, после Start — синий, после Scheduled — жёлтый, в день Due — оранжевый, после Due — красный; более срочная дата имеет приоритет.

`SafVaultTree` читает выбранную пользователем папку через Storage Access Framework. `VaultScanner` обходит `*.md`, исключает `.obsidian` и `.trash`, повторно использует неизменённые файлы и сохраняет прежние данные при ошибке чтения. `TaskParser`, `AgendaProjector` и `WidgetAgenda` не зависят от Android. `IndexCodec` и `LocalTaskIndex` хранят локальный индекс атомарно через платформенный `AtomicFile`. Robolectric API 36 на Windows требует тестовой адаптации семантики замены файла: Android предполагает замену существующего base при rename, а Windows host оставляет `.new`. Адаптация находится только в тестах и не входит в APK.

Checkbox передаёт непрозрачный ID строки в `TaskWidgetProvider`. Получатель проверяет случайный токен своего `PendingIntent`, текущий Vault и тег; `WidgetTaskAction` находит задачу в индексе. `TaskWriter` заново читает файл через `SafMarkdownDocumentAccess`, проверяет единственное точное совпадение исходной строки и отсутствие изменений между чтениями, записывает Markdown и подтверждает результат повторным чтением. При конфликте файл не изменяется. Незнакомое правило повторения отклоняется до записи.

`LocalTaskWriteJournal` хранит операции по выбранному Vault в SQLite. При успехе в журнале доступен Undo; он меняет только исходную строку и сохраняет посторонние правки. При сомнительном результате статус `NEEDS_RECOVERY` либо прерванный `PREPARED` оставляет резервную копию для экспорта и ручной проверки. Перед Undo журнал обновляет копию до текущего содержимого файла, включая посторонние правки. Обычная история ограничена 100 операциями на Vault; recovery-записи не удаляются автоматически. Миграция БД v1→v2 сохраняет старые записи с неизвестным Vault отдельно: recovery-копии можно экспортировать, но Undo этих записей запрещён, чтобы не записать их в чужой Vault. Автоматическое восстановление целого файла не выполняется, чтобы не затереть новые изменения.

Долгий обход Vault поддерживает прерывание до сохранения индекса и работает в `VaultScanJobService` через `JobScheduler`. Кнопка Refresh запускает однократное сканирование, периодическое задание с `setPersisted(true)` запрашивает обновление примерно раз в 30 минут с учётом ограничений Android и переживает reboot. Для этого manifest содержит нормальное разрешение `RECEIVE_BOOT_COMPLETED`; доступ в интернет не запрашивается. После записи или Undo приложение перечитывает только изменённый документ в индекс: соседние задачи той же заметки остаются видимыми сразу. Метаданные кэша этого документа сбрасываются, чтобы следующий полный обход повторно проверил файл. Ошибка фонового сканирования сохраняется и отмечается в заголовке виджета. Под заголовком видны `Обновляю...` и итог `Обновлено` либо ошибка. Успех истекает через 5 секунд по монотонным часам Android; отложенная перерисовка убирает сообщение, календарное время помогает после сна и перезапуска.

Настройки тега общие для Vault; шрифт и прозрачность сохраняются по `appWidgetId`. Нажатие на текст строит ссылку `obsidian://open?vault=…&file=…`. Приложение не запрашивает INTERNET и не выполняет синхронизацию; синхронизация Obsidian Vault остаётся внешней.

Решение по технологии: [ADR-001](docs/adr/ADR-001-widget-technology.md). Ограничения проверки: [TESTING.md](TESTING.md).
