# Предварительный аудит Robolectric 4.17

Дата: 2026-09-30. Цель: выполнять JVM-тесты Android Activity, SAF-адаптеров и служб для достижения общего покрытия 80% без устройства.

Проверены опубликованные [инструкция по подключению](https://robolectric.org/getting-started/), [релиз 4.17](https://github.com/robolectric/robolectric/releases/tag/robolectric-4.17) и [конфигурация модуля](https://github.com/robolectric/robolectric/blob/robolectric-4.17/robolectric/build.gradle.kts). Официальная инструкция подключает библиотеку через `testImplementation`; в APK она не входит. В просмотренной конфигурации не обнаружены install hooks либо задачи, изменяющие рабочие файлы проекта. Runner использует Maven dependency resolver и может скачать Android framework jar во время первого теста.

Риски: сторонний JVM-код выполняется с правами Gradle-процесса и может читать доступные ему локальные файлы и сеть; полный граф транзитивных зависимостей и исходников не аудирован. Планировались только синтетические тестовые Vault и отсутствие реальных секретов в тестах.

Автоматическая проверка безопасности отклонила команду добавления зависимости и запуска Gradle с причиной: сторонняя зависимость исполняется при сборке, а подтверждённого пользователем разрешения на её установку в доверенном контексте нет. Отклонённая команда ничего не изменила: `app/build.gradle.kts` по-прежнему содержит только JUnit. Запрошено отдельное разрешение пользователя. Обходить отказ другими средствами нельзя.
## Состояние после разрешения владельца, 2026-10-01

Владелец явно разрешил Robolectric 4.17 только в `testImplementation`. Зависимость подключена в `app/build.gradle.kts`; в APK она не входит. Полный suite на API 26/28/36 прошёл: 74 Android/JVM теста, общее покрытие 80,9%. Изолированная Windows-особенность Android 16 `AtomicFile` описана в [диагностике](atomicfile-api36-diagnosis.md). Предыдущий отказ автоматической проверки выше относится только к попытке до разрешения владельца.
