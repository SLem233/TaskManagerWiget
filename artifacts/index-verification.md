# Проверка индекса Vault и agenda

Дата: 2026-09-30. Статус: кандидат для проверки на Realme/Android 16.

APK: artifacts/vault-index-preview.apk. Размер: 919498 байт. SHA-256: 6a9bda43581f6172c950a18712f20c941800910512c25d1f1a038e9948f25dc7.

## Реализовано

- После первого полного обхода приложение сохраняет локальный индекс: идентификатор и путь файла, время модификации, размер, исходные строки и разобранные задачи.
- При повторном обходе неизменившиеся Markdown-файлы берутся из индекса, новые и изменившиеся читаются заново; удалённые убираются.
- При неизвестном времени или размере файл читается заново. При ошибке чтения папки или файла прежние задачи сохраняются, а ошибка показывается отдельно.
- Смена Vault или тега инвалидирует старый индекс. Повреждённый/несовместимый файл индекса вызывает полный перескан без потери исходных заметок.
- Agenda считает Просрочено только по прошлому Due; Scheduled и Start в прошлом попадают в Сегодня, задачи без дат — в конец; горизонт будущего — сегодня плюс 13 дней. Завершённые и отменённые задачи скрыты, порядок по приоритету и Due стабилен.
- Экран настройки показывает числа «заново», «из индекса», число задач и размер agenda. Виджет пока показывает тестовые данные, подключение реальных задач — следующий этап.
- Локальный индекс хранится во внутренней памяти приложения. Android backup отключён.

## Проверка на устройстве

1. Установить APK поверх предыдущей версии. При первом сканировании новая версия построит индекс, поэтому оно может снова занять около минуты.
2. Не меняя Vault, нажать «Сканировать Vault» второй раз. Ожидается «заново: 0» или мало файлов, а «из индекса» близко к числу Markdown-файлов. Сравнить длительность первого и второго обхода.
3. Изменить одну тестовую заметку с #task в Obsidian и повторить сканирование. Ожидается заново прочитанный изменённый файл и обновлённое число задач.
4. Проверить, что виджет пока по-прежнему показывает mock-задачи; это ожидаемо для данного этапа.

Фактическая скорость SAF и корректность индекса на Realme пока не проверены. Если провайдер не сообщает время/размер, повторный обход останется полным; числовой статус это покажет. Изменение содержимого при одновременно неизменных времени и размере также может остаться незамеченным до полного перескана — этот риск требует отдельного решения перед финальным выпуском.
