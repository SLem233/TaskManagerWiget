# ТЗ: Android-виджет задач для Obsidian Tasks

## 1. Назначение

Разработать лёгкое Android-приложение, основная функция которого — **домашний виджет (AppWidget) со списком задач из локального Obsidian Vault**.

Приложение не должно дублировать Obsidian и не должно превращаться в отдельный task manager.

Основной сценарий:

1. Пользователь один раз открывает приложение.
2. Выбирает Obsidian Vault.
3. Настраивает виджет.
4. После этого работает с задачами **не открывая приложение**:
   - видит текущие и будущие задачи;
   - прокручивает список;
   - отмечает задачи выполненными;
   - обновляет список;
   - при необходимости открывает исходную заметку в Obsidian.

Внешне виджет должен быть максимально близок по стилю к календарному agenda-виджету пользователя, чтобы оба виджета можно было разместить рядом на одном Android-экране и они выглядели как единая система.

---

# 2. Главный принцип UI

## Референс

В качестве визуального референса использовать предоставленный скриншот календарного agenda-виджета.

Ключевые свойства референса:

- чёрная / тёмная тема;
- практически отсутствует отдельная «карточка» вокруг всего виджета;
- фон визуально сливается с тёмными обоями;
- белый основной текст;
- вторичный текст — серый;
- компактное вертикальное размещение;
- группировка записей по датам;
- дата / день недели визуально отделяют группы;
- элементы расположены плотно, без крупных карточек;
- минималистичные иконки;
- скроллируемый список;
- виджет занимает значительную часть экрана и хорошо использует высоту;
- верхняя строка содержит компактные управляющие элементы;
- размеры виджета пользователь может изменять непосредственно на рабочем столе Android.

Цель: при размещении календаря и задач рядом они должны выглядеть как два модуля одной визуальной системы.

# 3. Что является задачей

Не считать задачей каждый Markdown checkbox.

Обрабатывать **только строки, содержащие тег `#task`**.

Пример:

```md
- [ ] Обсудить с командой #task #project/DemoProject 🛫 2026-10-01 ⏳ 2026-10-10 📅 2026-10-25
```

Это задача.

Пример:

```md
- [ ] Проверить формат имени файла
```

Это обычный чек-лист и в виджет попадать не должен.

---

# 4. Источник данных

Приложение работает с локальным Obsidian Vault.

При первом запуске:

1. Пользователь выбирает корневую папку Vault через Android Storage Access Framework.
2. Приложение сохраняет persistent URI permission.
3. Приложение сканирует Markdown-файлы `*.md`.

По умолчанию игнорировать:

```text
.obsidian/
.trash/
```

В настройках должна быть возможность добавить другие исключаемые папки.

Не использовать облачный backend.

Не требовать аккаунт.

Не передавать данные в интернет.

Не использовать `MANAGE_EXTERNAL_STORAGE`, если всё можно реализовать через SAF.

# 5. Поддерживаемый синтаксис Obsidian Tasks

## Checkbox

```md
- [ ] Открытая задача
- [x] Выполненная задача
```

Допустимо учитывать `X` как выполненную задачу.

---

## Даты

Поддержать:

```text
🛫 YYYY-MM-DD   Start
⏳ YYYY-MM-DD   Scheduled
📅 YYYY-MM-DD   Due
```

Пример:

```md
- [ ] Подготовить презентацию #task #project/DemoProject 🛫 2026-10-01 ⏳ 2026-10-10 📅 2026-10-25
```

Парсер должен получить:

```text
description = Подготовить презентацию
project = DemoProject
start = 2026-10-01
scheduled = 2026-10-10
due = 2026-10-25
completed = false
```

Служебные emoji, даты, `#task` и `#project/...` не показывать в основном названии задачи.

---

## Приоритеты

Поддержать синтаксис Obsidian Tasks:

```text
⏫ Highest
🔼 High
🔽 Low
⏬ Lowest
```

Приоритет влияет на сортировку задач внутри одного дня.

---

## Проекты

Поддержать:

```text
#project/PROJECT_NAME
```

Например:

```text
#project/DemoProject
```

В UI отображать короткое имя проекта:

```text
DemoProject
```

---

## Дополнительные теги

Поддержать как минимум:

```text
#waiting
#someday
```

MVP может только распознавать их.

Расширенная фильтрация — после MVP.

# 6. Логика дат

## Start

`🛫 Start` означает:

> не показывать задачу как актуальную до наступления этой даты, если у неё нет более ранней логически необходимой даты.

Start не является основной датой размещения задачи в agenda.

---

## Scheduled

`⏳ Scheduled` — основная дата, когда пользователь собирается выполнять задачу.

Именно по этой дате задача должна попадать в соответствующую секцию agenda.

---

## Due

`📅 Due` — deadline.

Due показывается как дополнительная информация:

```text
до 25 окт.
```

---

## Выбор даты размещения задачи

Использовать:

1. `Scheduled`, если он указан.
2. Иначе `Due`.
3. Иначе — секция `Без даты`, если она включена в настройках.

Пример:

```text
Start      1 октября
Scheduled 10 октября
Due       25 октября
```

Виджет показывает задачу в группе:

```text
10 октября
```

и дополнительно:

```text
DemoProject · до 25 окт.
```

---

# 7. Просроченные задачи

Если:

```text
Due < today
AND completed = false
```

показывать задачу сверху в отдельной секции:

```text
Просрочено
```

Просроченную задачу не дублировать в основной agenda.

Секция должна быть визуально заметной, но не использовать яркий большой warning-card.

Стиль должен оставаться близким к календарному виджету.

# 9. Требования к внешнему виду

## 9.1. Общий стиль

Основная тема — чёрная / dark.

Визуально ориентироваться на предоставленный календарный widget.

Не использовать Material-card дизайн с крупными закруглёнными карточками вокруг каждой задачи.

Не использовать яркие цветные блоки по умолчанию.

Не использовать градиенты.

Не использовать тени.

Дизайн должен быть максимально плоским и компактным.

---

## 9.2. Фон

По умолчанию:

```text
чёрный с высокой прозрачностью
```

Должна быть настройка opacity:

```text
0–100 %
```

Предусмотреть вариант:

```text
0 % — полностью прозрачный
```

При прозрачном фоне текст всё равно должен хорошо читаться на тёмных обоях.

---

## 9.3. Цвет текста

По умолчанию:

```text
основной текст      белый
вторичный текст     серый
заголовки дат       серый / светло-серый
checkbox            белый / светло-серый
```

Цвета должны выглядеть близко к календарному виджету на референсе.

Допустимо использовать системные цвета Android, но внешний результат должен сохранять чёрно-белую минималистичную стилистику.

---

## 9.4. Типографика

Главное название задачи:

```text
14–17 sp в зависимости от выбранного масштаба
```

Вторичный текст:

```text
11–14 sp
```

Заголовок группы:

```text
14–18 sp
```

Должны быть настройки:

```text
Small
Medium
Large
```

# 10. Изменяемый размер виджета

Это обязательное требование.

Пользователь должен иметь возможность стандартным способом Android изменить размер виджета на рабочем столе.

Виджет должен корректно перестраиваться при изменении:

- ширины;
- высоты;
- количества занимаемых колонок;
- количества занимаемых строк.

Минимальный рекомендуемый размер:

```text
4 × 2
```

Основной сценарий:

```text
4 × 5
4 × 6
5 × 5
5 × 6
```

Не привязываться к конкретной сетке launcher.

---

## Поведение при изменении ширины

При уменьшении ширины:

- длинные названия задач обрезать ellipsis;
- не допускать горизонтального скролла;
- вторичную информацию при необходимости сокращать;
- элементы управления не должны налезать друг на друга.

Пример:

```text
Обсудить с командой…
DemoProject · до 25 окт.
```

---

## Поведение при изменении высоты

Высота определяет количество одновременно видимых задач.

Список остаётся вертикально прокручиваемым.

При увеличении высоты должен отображаться больший фрагмент agenda, а не увеличиваться вертикальный padding.

---

# 11. Скролл

Не открывать приложение для просмотра следующих задач.

По поведению ориентироваться на agenda/calendar widget пользователя.

# 13. Checkbox непосредственно в виджете

Нажатие на checkbox задачи должно работать **без открытия приложения**.

Исходная строка:

```md
- [ ] Подготовить презентацию #task ...
```

после выполнения:

```md
- [x] Подготовить презентацию #task ...
```

После записи:

1. обновить внутренний индекс;
2. обновить widget;
3. выполненная задача должна исчезнуть из активного списка.

# 14. Защита Markdown от повреждения

Перед изменением checkbox повторно прочитать исходный файл.

Для каждой задачи хранить:

```text
source URI/path
source file
line number
original full line
hash
```

Алгоритм:

1. Проверить строку по сохранённому номеру.
2. Если она совпадает — изменить.
3. Если номер строки изменился — искать точное совпадение строки.
4. Если найдено одно совпадение — изменить его.
5. Если найдено несколько одинаковых совпадений — не изменять автоматически.
6. Если задача не найдена — не перезаписывать файл.
7. Показать краткое сообщение об ошибке / необходимости refresh.

Нельзя сохранять целый старый snapshot файла поверх более новой версии.

```text

```

Использовать:

```text

```

Минимум передавать:

```text

```

Если возможно корректно перейти к строке / block id — реализовать.

Если такой переход ненадёжен, достаточно открыть нужный файл.

# 21. Автоматическое обновление

Обновлять widget:

- после checkbox;
- после ручного Refresh;
- после возврата из настройки;
- периодически через WorkManager.

Периодическое обновление не должно быть чрезмерно частым.

Рекомендуемый интервал:

```text
15–30 минут
```

с учётом ограничений Android.

Также при открытии Obsidian и последующем возвращении на home screen допускается обновление при следующем системном update event.

# 22. Производительность

Vault потенциально содержит большое количество Markdown-файлов.

Нельзя перечитывать весь Vault при каждой перерисовке widget.

Создать индекс.

Для каждого файла хранить как минимум:

```text
URI
lastModified
parsed tasks
```

При следующем scan:

- новый файл → parse;
- changed file → parse;
- unchanged file → использовать cache;
- deleted file → удалить его задачи из index.

# 28. MVP

В MVP реализовать только:

1. Выбор Obsidian Vault.
2. SAF permission.
3. Сканирование `*.md`.
4. Только задачи с `#task`.
5. Парсинг:
   - checkbox;
   - description;
   - project;
   - Start;
   - Scheduled;
   - Due;
   - priority.
6. Локальный индекс.
7. Настоящий Android home-screen widget.
8. Widget можно resize на рабочем столе.
9. Чёрная / прозрачная тема как у календарного референса.
10. Вертикальный scroll непосредственно в widget.
11. Группы:
    - Просрочено;
    - Сегодня;
    - Завтра;
    - будущие даты.
12. Горизонт 14 дней.
13. Checkbox непосредственно в widget.
14. Refresh непосредственно в widget.
15. Нажатие на задачу открывает заметку в Obsidian.
16. Собираемый installable APK.

Не делать в MVP:

- отдельный task manager;
- календарный экран приложения;
- Quick Add;
- recurrence editor;
- уведомления;
- drag & drop;
- синхронизацию;
- backend.

# 29. Acceptance Criteria MVP

MVP считается готовым, если выполняется следующий сценарий.

В Obsidian есть строка:

```md
- [ ] Обсудить с командой #task #project/DemoProject 🛫 2026-10-01 ⏳ 2026-10-10 📅 2026-10-25
```

Сегодня:

```text
30 сентября 2026
```

После добавления widget на Android home screen:

1. Widget отображается без запуска основного приложения.
2. Widget можно растянуть по высоте и ширине.
3. Widget имеет чёрную/прозрачную стилистику, совместимую визуально с календарным widget.
4. Можно прокрутить agenda непосредственно на рабочем столе.
5. В списке видна группа:

```text
10 октября
```

6. В ней есть:

```text
☐ Обсудить с командой
  DemoProject · до 25 окт.
```

7. Нажатие checkbox меняет исходный Markdown на:

```md
- [x] Обсудить с командой #task #project/DemoProject 🛫 2026-10-01 ⏳ 2026-10-10 📅 2026-10-25
```

8. Задача исчезает из widget.
9. Нажатие на название задачи открывает исходную заметку в Obsidian.
10. После изменения Markdown в Obsidian кнопка `↻` обновляет widget.
11. Обычные checklist строки без `#task` не появляются.

# 32. UX-принцип проекта

Главное правило:

> Пользователь не должен открывать приложение, чтобы посмотреть задачи.

Приложение — конфигуратор.

Widget — основной продукт.

По визуальному стилю widget должен восприниматься как соседний модуль календарного agenda-widget пользователя, а не как отдельное Android-приложение.
